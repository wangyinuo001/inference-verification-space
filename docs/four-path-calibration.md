# Verification Space 四条路径校准

本轮选取文本生成、前缀复用、运行中取消和张量并行生成，对照固定版本的 vLLM 与 SGLang 源码及测试断言。逐单元证据见[路径证据表](../semantic_space/trace-unit-evidence.tsv)；表中的测试位置表示已定位到相关代码，具体路径条件和检查性质仍按下述源码判定。

| 路径 | 两套实现共同需要检查的性质 | 已定位的判定 | 路径条件与证据的差异 |
| --- | --- | --- | --- |
| 文本生成 | 同一请求的输入、调度位置、模型结果、采样结果与最终响应保持对应 | vLLM [模型生成测试](https://github.com/vllm-project/vllm/blob/76a0ccc209343971c6f4b56f6380a76202428385/tests/models/language/generation/test_common.py#L117)与 HF 比较 token 和候选信息；SGLang [模型生成测试](https://github.com/sgl-project/sglang/blob/49e384ce9d304648e9959666ecb8ce8cd98d0deb/test/registered/models/test_generation_models.py#L137)通过运行器比较输出文本和 logprob。两个判定采用各自的输入配置和容差。 | 现有模型对照证明所测配置中的局部结果关系；把接纳、调度、计算和返回连为同一请求，仍需记录请求身份与每次交接的 token 位置。 |
| 前缀复用 | 命中范围、隔离键、缓存生命周期和复用后的计算结果分别成立 | vLLM [缓存结果测试](https://github.com/vllm-project/vllm/blob/76a0ccc209343971c6f4b56f6380a76202428385/tests/v1/e2e/test_cpu_linear_attn_chunked_prefix.py#L94)先确认命中，再以 `check_logprobs_close` 对照冷缓存；SGLang [缓存结果辅助检查](https://github.com/sgl-project/sglang/blob/49e384ce9d304648e9959666ecb8ce8cd98d0deb/python/sglang/test/kl_test_utils.py#L219)确认命中后，比较复用输出 logprob 与重新计算的输入 logprob。 | 当前模板写 `token_ids` 输入；所引 vLLM 测试传入文本提示词，SGLang 辅助检查传入 token IDs。因此两者支撑共同的前缀语义，但不能据此说它们覆盖同一个 API 输入形式。 |
| 运行中取消 | 取消状态、其他请求继续执行、迟到输出处理和资源释放是四项不同检查 | vLLM [最后一步取消测试](https://github.com/vllm-project/vllm/blob/76a0ccc209343971c6f4b56f6380a76202428385/tests/v1/engine/test_abort_final_step.py#L144)断言最终 `finish_reason=abort`，[多请求测试](https://github.com/vllm-project/vllm/blob/76a0ccc209343971c6f4b56f6380a76202428385/tests/v1/engine/test_engine_core.py#L176)断言仅目标请求退出运行队列；SGLang [HTTP 取消测试](https://github.com/sgl-project/sglang/blob/49e384ce9d304648e9959666ecb8ce8cd98d0deb/test/manual/entrypoints/http_server/test_abort_request.py#L93)检查取消原因，[选择性取消测试](https://github.com/sgl-project/sglang/blob/49e384ce9d304648e9959666ecb8ce8cd98d0deb/test/manual/entrypoints/http_server/test_abort_request.py#L133)还断言另外两个请求正常完成。 | 所引 HTTP 测试没有断言缓存块释放，也没有记录迟到计算结果是否再次交付；当前路径的 `partial_hit` 条件亦未由这些断言确认。已将原先误挂在清理和迟到输出下的测试锚点移至实际检查的性质。 |
| 张量并行生成 | 每个 rank 的输入与权重分片、跨卡归约和模型最终输出分别符合逻辑模型 | vLLM [通信测试](https://github.com/vllm-project/vllm/blob/76a0ccc209343971c6f4b56f6380a76202428385/tests/distributed/test_custom_all_reduce.py#L850)与 PyTorch `all_reduce` 比较；SGLang [JIT 通信测试](https://github.com/sgl-project/sglang/blob/49e384ce9d304648e9959666ecb8ce8cd98d0deb/test/registered/jit/test_custom_all_reduce.py#L181)与 NCCL 结果比较。[vLLM 分片实现](https://github.com/vllm-project/vllm/blob/76a0ccc209343971c6f4b56f6380a76202428385/vllm/model_executor/layers/linear.py#L1839)与[SGLang 分片实现](https://github.com/sgl-project/sglang/blob/49e384ce9d304648e9959666ecb8ce8cd98d0deb/python/sglang/srt/layers/linear.py#L1523)均按 rank 选输入切片。 | 当前未定位到逐 rank 核对切片、权重版本和局部输出次序的直接断言；通信测试和模型结果测试使用的配置也不能自动合并成同一次 TP=2、FP16 请求的整体证明。 |

此次校准使取消路径新增 `abort.terminal_status` 和 `abort.other_requests_progress` 两个验证单元，并保留 `abort.no_late_output` 与 `abort.cleanup` 作为独立待检查性质。四条路径说明，空间单元应按可观察性质划分；输入形式、缓存状态、取消时机和并行拓扑作为适用条件记录。同一测试可支撑多个单元，但每个关联都应有实际断言与条件依据。下一轮优先补充运行中取消的事件序列、TP 分片逐 rank 判定，以及文本生成各交接的同一请求身份记录，并将其写成独立仓库的测试规格。

在[源码派生模型](../source_model/space_model.json)中，这些取消检查分别对应 `out.finish_reason`、新增的 `sched.abort_unaffected`、新增的 `out.no_late_output`，以及 `sched.abort` 与 `kv.release_terminal`。前者检查终止原因，后两项分别检查迟到输出和资源所有权，因而不会把一次取消请求的 HTTP 成功响应计作资源清理或输出抑制的判定。
