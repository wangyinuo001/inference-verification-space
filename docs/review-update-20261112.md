# 11 月 12 日：测试归类与验证空间更新

本轮重新读取全部 31,968 个源码入口，核对了测试定义、继承方法、源码哈希、已审性质和运行记录。索引中的 29,879 个 Python 定义、1,366 个继承方法候选和 630 个 Rust 定义均定位到源码，另外 93 条继续按文件记录。检查内容已经核对并归入候选空间的入口由 5,330 增至 6,469，本轮增加 1,139 条，涉及 223 个文件。逐项记录见[完整清单](../semantic_space/test_mapping_pilot/full_delivery/all-entries.tsv)，后续工作按[目录与检查方式](../semantic_space/test_mapping_pilot/full_delivery/pending-groups.tsv)组织。

两批远端 CPU 任务均已结束，165 个文件的原始材料已回收到本地并核验归档及内部文件哈希。108 个文件的 pytest 运行通过，27 个返回测试失败，17 个收集出错，7 个超时，5 个未记录到测试体，1 个未收集到测试。逐调用记录对应到 2,119 个源码入口、2,201 个运行实例；1,878 个入口同时观察到产品调用和断言。另有 30 个运行实例未对应到源码索引，独立保留。运行采用隔离导入、隐藏 GPU 的条件，失败记录需结合环境及调用阶段解释。[运行汇总](../semantic_space/test_mapping_pilot/background_evidence/summary.json)

源码审查实际修改了空间的定义。提示词文本构造与 token ID 编码分开，媒体占位标记与载荷或张量绑定分开，采样前 logit 变换与最终 token 采样分开。这三项均补充了两个框架的实现和测试依据。另合入此前已完成的草稿候选绑定单元。候选交互空间现有 119 个单元；源码派生模型仍为 76 个单元，两者的逐项统一仍在进行。

审查同时纠正了几类误配。语法编译缓存不归入 KV 缓存；mock 传输函数只检查调用参数时，不归入缓存内容搬运正确；循环检查事件却没有断言事件存在时，不据此声称检查了事件产生。数值测试记录实际参考来源、返回字段、精度、容差和运行条件；vLLM 的部分惩罚测试检查排名及历史 token 的成员关系，与 SGLang 的具体 logit 数值断言分别记录。

目前的交付是有逐项记录和源码依据的候选归类与空间修订。全量源码定位已完成，全部入口的语义审查尚未完成。后续集中处理剩余性质、跨函数辅助检查和状态条件，并统一交互空间与源码派生模型；不以重新扫描次数或运行通过数量代替已确认归类数量。
