# 工具调用解析验证规格

工具调用解析接收模型生成的文本或文本片段，输出普通文本与有序的工具调用。每个调用包含工具名称和结构化实参。验证单元 `tool.call_parse_relation` 检查这三者的对应关系，并记录解析器对不完整输入和错误输入的处理。它位于模型输出到接口交付之间；生成前的工具约束构造、生成后的参数类型绑定另有验证单元。

验证条件包括工具语法、完整或流式模式、片段边界、普通文本的位置、特殊标记、未知工具以及解析失败的处理策略。对同一语义调用，分别提供完整输出与多种分块方式，检查普通文本、工具名称、调用顺序和实参；片段尚未闭合时检查缓冲状态及是否提前发出调用。无工具调用、嵌套实参、并行调用、转义字符和解析失败分别构造样本。预期结果应依据该次运行声明的策略生成，不能假定两套框架的失败处理相同。

vLLM 的 Pythonic parser 在完整输出中识别方括号调用，并用增量解析处理流式片段。其官方测试检查无调用文本、工具名称和实参、多段输入中的三个调用，以及正则超时后将输入作为普通文本返回。SGLang 的 Pythonic detector 还测试工具调用前后普通文本、嵌套列表或字典、跨块未闭合调用，以及 `<|python_start|>` 与 `<|python_end|>` 标记。两者共有的验证目标是“生成文本与解析结果的关系”；标记、包围文本和失败策略作为各自适用条件保留。

源码证据见 `experiments/semantic_space/vllm-pythonic-tool-source-review.tsv` 与 `experiments/semantic_space/sglang-pythonic-tool-source-review.tsv`。两张表逐测试入口记录断言行、检查性质和适用条件；这些是源码审阅结果，运行实例的结论需另行执行取得。
