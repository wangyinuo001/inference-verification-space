# 验证空间测试入口第三轮全量扫描

本轮在前两轮的 31,968 条索引记录上重新读取固定源码，增加两类此前未统一提取的证据：测试断言采用什么检查形式，以及测试调用同文件辅助函数后，辅助函数是否继续调用产品代码。脚本逐文件解析源码，最多沿同文件辅助函数追踪两层，保留每项测试的原候选领域及已有人审结论；运行约 20 秒。[逐项结果](third-pass-all-tests.tsv)与[汇总](third-pass-all-tests.json)由 `experiments/.venv/bin/python experiments/semantic_space/third_pass_full_scan.py` 生成。

31,968 条均有输出；31,269 条入口所在的 Python 文件成功解析，699 条为非 Python 或当前无可解析源码。27,359 条找到可识别的断言形式，其中 3,540 条已有产品调用结果进入断言的直接源码关联，23,819 条只有尚未绑定被测调用的断言；另有 4,609 条未在当前抽取范围内定位到断言。断言形式包括相等、数值容差、异常、形状、dtype、数量与状态码等，表示**怎样写检查**，并不单独确定被检查的系统性质。

同文件辅助函数追踪为 8,467 条入口找到可能的产品调用；其中 4,773 条此前没有直接产品调用记录。这些线索有助于继续追查经过 helper 的测试路径，但辅助函数中的构造、参考计算和真正被测操作仍可能混在一起，静态调用存在也不等于特定参数实例执行了这条路径。因此本轮没有将这些入口自动升级为已确认空间映射。已有 1,191 条局部源码性质记录和 838 条单元映射保持原证据等级；第二轮 62 条逐项审查结论也继续保留。

下一步先处理“有辅助调用、有断言、但两者尚未关联”的入口，确认 helper 返回值或状态如何进入断言，再抽取输入与运行条件。跨框架空间单元仍依据源码行为和被检查性质修订，不能由测试名、断言形式或辅助函数所在模块直接确定。
