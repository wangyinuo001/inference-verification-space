# vLLM 运行行为测试源码核对
本批核对 174 个测试入口，涉及 11 个测试文件及 4 个共享 fixture 文件。范围包括 DecodeBench 人工缓存填充、远程 prefill 调度、卸载任务完成、UMBP 事件、Nixl 心跳、存储指标、权重更新会话、VMM 缓存及 GPU worker 初始化与资源借用。每项结论以该入口的实际断言为准，保存了源码、调用表达式、参数化条件及文件 SHA-256。
测试使用真实 CPU 张量、设备张量、替身后端和人工完成通知的情况分别记录在 conditions。远程 prefill 运行真实调度器，但模型输出与接收完成通知由测试构造；权重更新会话用记录型 runner/engine；HF3FS 使用仓库本地文件 mock。CUDA/VMM 测试本轮只阅读源码，没有执行设备实验。
新增六个候选单元用于表达人工缓存初始化、权重更新会话、物理页提交与视图、临时资源作用域、休眠参数保留以及启动容量计划复用。生产源码片段与 SHA-256 见 product-source-evidence.json。HF3FS flush/close 入口没有显式清理状态断言，单独列入 excluded-reviewed.json。
同时核对先前批次使用的单元语义，给出 36 项纠正建议。原“按逻辑页计数”的单元不适合存在布尔值/命中状态测试，改提存储存在性单元；Mooncake 休眠测试仅核查注册生命周期，不支持传输地址区间性质；PCP 暴露输入缓冲区的测试改归来源存储绑定。纠正建议保留原单元与原因，未修改旧批次或共享空间。
forward buffer 存储单元补充 vLLM 持久缓冲来源及 microbatch 独立存储证据，并说明 SGLang 注册键机制与 vLLM 批次持久缓冲机制的差异。共用的是存储来源和隔离要求，不把 vLLM 测试扩展成注册顺序无关的证明。
已检查 174 个映射均唯一、oracle_source 为纯路径加行号、15 个文件 hash 与快照一致，八个候选单元（六个本批加两个纠正）均具完整 schema、现有条件维度及 vLLM 产品源码锚点。
