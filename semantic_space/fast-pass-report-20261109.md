# 两套推理框架测试入口的全量快速初筛

本轮在固定 vLLM 与 SGLang 0.5.14 源码索引上，对 31,968 条记录逐条合并已有的入口解析、候选领域、调用与断言关联、源码审查及继承关系；扫描本身约 0.6 秒。结果保存为[逐项表](fast-pass-all-tests.tsv)、[分组队列](fast-pass-review-families.tsv)和[汇总](fast-pass-all-tests.json)，可用 `experiments/.venv/bin/python experiments/semantic_space/fast_pass_all_tests.py` 重建。31,968 条中包括源码测试定义、继承方法候选、Rust 测试及少量文件级记录；150 条已被实际继承入口替代的文件占位记录没有重复计数。每条都有候选领域、证据等级、风险标记和下一步核查动作。候选领域用于找审查对象，只有具备源码审查和断言证据的条目才记录已检查的局部性质。

| 当前证据状态 | 条目数 | 本轮可以据此做什么 |
| --- | ---: | --- |
| 已核对局部源码性质 | 1,191 | 其中 838 条已映射空间单元，其余需继续连接单元或条件 |
| 已读源码但性质或空间单元待细化 | 472 | 集中整理缺少的验证性质与判定边界 |
| 调用结果到断言的源码关联候选 | 3,294 | 继续绑定输入、状态及被检查的性质 |
| 其他静态调用、辅助链或 HTTP 关联候选 | 7,335 | 核对被测目标、参考值和实际执行边界 |
| 尚未建立足够关联 | 19,598 | 按直接断言、间接断言、helper、继承、Rust 等原因分流 |
| 已核对为范围外或跳过 | 78 | 保留在仓库索引，不作为请求行为覆盖 |

快速初筛发现，24,582 条候选领域主要依据测试名或目录。为核查这类依据，从两个框架分别抽取 80 条并回读测试体及必要辅助函数。vLLM 样本中 44 条与主检查对象大体一致、11 条只表达了部分内容、25 条主对象错位；SGLang 样本中对应为 46、11、23 条。抽样按归类依据和领域分层，数字不能外推为全库准确率。错误类型包括把 MoE topk 算子归为生成采样、把配置映射归为分布式执行，以及把工具约束构造归为输出解析。逐项来源见 [vLLM 核查](agent_vllm_weak_review.tsv)和 [SGLang 核查](agent_sglang_weak_classification_review.tsv)。因此，后续规则把名称和目录仅作为候选召回，继续依据实际调用、输入、状态和断言确定检查性质；一个测试涉及多个对象时保留多个候选领域。

对缺少直接调用—断言关联的 22,541 条入口，还进行了全量原因分组和 50 条分层源码抽查，见[独立分诊](agent_unlinked_routing_audit.md)。抽查发现原来的单个“调用类别”有时混合了 fixture 来源、HTTP 请求和真正被检查的操作。本轮逐项表已经将调用来源、helper 线索、HTTP 线索和判定形式分列。下一轮应先处理这些有明确源码线索的组，再从实际检查性质反推空间中需要新增或拆分的单元；同组测试不会自动继承代表样本的验证结论。
