| 1 | **Physical allocation: fixed blocks/pages** — vLLM `block_pool.py:139-158`, `BlockPool.__init__`, `get_new_blocks:628-660`; SGLang `allocator/paged.py:102-192`, `PagedTokenToKVPoolAllocator.alloc_extend` | vLLM owns `KVCacheBlock[]`, free doubly-linked queue, `ref_cnt`; SGLang owns page indices and `free_pages` | Double allocation, lost page, free-list corruption, OOM despite apparent capacity | At quiescence, `allocated + free == total`; every returned ID is unique and in range. **LOCAL** | vLLM allocates block objects and tracks references; SGLang paged allocator returns physical page IDs and separately maps them to token positions. |
| 2 | **Request logical→physical mapping** — vLLM `single_type_kv_cache_manager.py:390-467`, `add_local_computed_blocks`; SGLang `memory_pool.py:229-290`, `ReqToTokenPool.alloc/free` | vLLM `req_to_blocks[request_id]`; SGLang dense `req_to_token[req_pool_idx, token_pos]`, plus request-pool rows | Stale row after request reuse, wrong request row, leaked row, use-after-free physical slot | Every active request has exactly one valid mapping; freed request row is reusable only after its KV indices are released. **LOCAL** | vLLM mapping is block-granular; SGLang mapping is token-slot-granular, even when physical allocation is paged. |
| 3 | **Full-block prefix key construction** — vLLM `kv_cache_utils.py:635-676`, `generate_block_hash_extra_keys`; `block_pool.py:262-303`, `cache_full_blocks`; SGLang `radix_cache.py:311-327`, `RadixKey.hash_page` | vLLM chained request block hashes and group IDs; SGLang token/page hash chain (`prior_hash`) and `extra_key` | Stale hit if any KV-affecting input omitted; collision/namespace confusion; hit across incompatible adapters or inputs | Equal prefix keys imply equal reusable KV values; differing KV-affecting inputs must not match. **Requires model execution for equality; key isolation is LOCAL** | vLLM hashes full blocks and chains over prefix; SGLang hashes radix segments/pages and can use token-level tree structure. |
| 4 | **LoRA/cache-salt/MM isolation** — vLLM `kv_cache_utils.py:600-676`, `_gen_lora_extra_hash_keys` / `generate_block_hash_extra_keys`; SGLang `radix_cache.py:291-310`, `RadixKey` and `match_prefix` | vLLM extra-key tuple contains LoRA, multimodal, prompt-embedding hashes, first-block `cache_salt`; SGLang `RadixKey.extra_key` namespaces the tree | Cross-LoRA hit; cross-cache-salt hit; cross-MM/prompt-embedding hit | Prefix match with different LoRA, salt, MM features, or prompt embeddings must be false. **LOCAL** | vLLM explicitly derives MM/LoRA/salt/prompt-embedding components; SGLang relies on caller-provided `extra_key`, so completeness of caller namespace is a condition. |
| 5 | **Prefix hit lookup** — vLLM `kv_cache_manager.py:289-353`, `get_computed_blocks`; coordinator `kv_cache_coordinator.py:464+`; SGLang `radix_cache.py:408-435`, `match_prefix` | vLLM cached block lookup and per-group hit lengths; SGLang radix traversal, returned physical indices, terminal nodes | Returning blocks from wrong group/tree; stale indices; hit length exceeding request or cached value length | Returned mapping length equals reported hit length and indices contain the requested prefix KV. **Model execution needed for output equivalence** | vLLM hit is normally full-block aligned and deliberately recomputes the last token (`kv_cache_manager.py:327-333`); SGLang `page_aligned(page_size)` truncates match to page boundaries (`radix_cache.py:408-435`). |
| 6 | **Partial-block hit / copy-on-write** — vLLM `single_type_kv_cache_manager.py:173-181`, `_has_partial_local_hit`; `get_num_blocks_to_allocate:245-263`; SGLang `radix_cache.py:408-435`, `match_prefix` plus node split | vLLM `_partial_hit_reqs`, private CoW block and pending copies; SGLang splits radix node when match ends inside stored segment | Shared tail overwritten, partial hit counted as full, leaked private block, output divergence | A request must never mutate a physical KV block still referenced by another request. **LOCAL structure; output equivalence needs execution** | vLLM explicitly reserves an extra CoW block for non-aligned local hits; SGLang can structurally split a node to expose an exact token boundary, but physical page alignment still constrains returned KV. |
| 7 | **Reference protection / locking** — vLLM `block_pool.py:767-781`, `touch`; `free_blocks:791-832`; SGLang `radix_cache.py:632-671`, `inc_lock_ref/dec_lock_ref` | vLLM block `ref_cnt` and free-queue membership; SGLang node `lock_ref`, `evictable_size_`, `protected_size_` | Double decrement, negative refcount, eviction of active prefix, block remains permanently pinned | No in-use block/node is evicted; each acquire has exactly one release. **LOCAL** | vLLM references physical blocks directly; SGLang propagates lock counts from terminal node to root, protecting whole radix paths. |
| 8 | **Eviction policy** — vLLM `block_pool.py:791-832`, `free_blocks`; `834+`, `evict_blocks`; SGLang `radix_cache.py:637-671`, `evict`; `evict_policy.py:16-62` | vLLM free queue ordering, hash table, block refs; SGLang `evictable_leaves`, heap priority, node values | Evict in-use node, stale hash entry, freeing value twice, parent promoted incorrectly | Eviction removes only unreferenced cache state and removes corresponding lookup metadata. **LOCAL** | vLLM uses queue ordering for cached-block LRU-like behavior; SGLang supports LRU/LFU/SLRU/priority strategies and evicts radix leaves, potentially cascading to parents. |
| 9 | **Free on finished request** — vLLM `kv_cache_manager.py:650-702`, `free`, `evict_blocks`; SGLang `radix_cache.py:467-520`, `cache_finished_req` | vLLM request block list and coordinator references; SGLang request KV indices, radix node references, allocator free list | Finish path leaks blocks; abort/free twice; cached blocks freed while radix tree still owns them | After finish/abort, request-owned references are gone, while cached prefix references remain valid. **LOCAL** | SGLang explicitly frees duplicate/non-cached and unaligned tail indices while retaining tree-owned indices (`cache_finished_req`); vLLM decrements block refs and leaves cached zero-ref blocks as eviction candidates. |
| 10 | **Unfinished/chunked request retention** — vLLM `single_type_kv_cache_manager.py:390-467`; SGLang `radix_cache.py:520-610`, `cache_unfinished_req` | vLLM request block table and prefix-hit refs; SGLang `cache_protected_len`, `prefix_indices`, `last_node`, `req_to_token` | Partial-page tail leaked, old node lock not released, stale request mapping after rematch | Repeated chunk transitions preserve exactly one current request mapping and no duplicate ownership. **LOCAL** | SGLang documents that partial page/bigram tail is retained outside the tree and freed on a later transition/finalization; vLLM’s block accounting is block-aligned and has explicit partial-hit CoW bookkeeping. |
| 11 | **Sliding-window / sparse retention** — vLLM `block_pool.py:253-303`, masked/null blocks; `single_type_kv_cache_manager.py:219-263`; SGLang `allocator/swa.py:309-341`, `common.py:66+` | vLLM block masks, null blocks, skipped-token/block accounting; SGLang SWA allocator and out-of-window slot recycling | Reuse of an out-of-window slot still read by attention; wrong skipped-block count; null block accidentally freed | Physical slots outside retention window may be recycled only after no kernel can read them. **Needs model/kernel execution** | vLLM retains full block objects but skips/null-masks blocks from prefix hash; SGLang recycles token slots/pages according to SWA window, so logical mapping may be non-prefix-contiguous. |
| 12 | **Hybrid/Mamba state cache** — vLLM `single_type_kv_cache_manager.py:311-345`, sparse/mamba admission and boundary state comments; `kv_cache_coordinator.py:943+`, `find_longest_cache_hit_per_group`; SGLang `memory_pool.py:646-884`, `HybridReqToTokenPool`, `free_mamba_cache` | vLLM per-group block tables, divergent group hit lengths, boundary-state offload records; SGLang token mapping plus Mamba state slots/pools | Attention and Mamba hit boundaries disagree; stale state at boundary; state freed while request still active | Every reused token boundary has a matching valid state for every stateful layer/group. **Needs model execution** | vLLM explicitly permits per-group divergence and pins/reconciles a shared boundary; SGLang has hybrid request/token pools and separate Mamba-cache freeing semantics. |

| 14 | **KV events** — vLLM `block_pool.py:287-303`, `cache_full_blocks`; `block_pool.py:834+`, eviction/removal events; SGLang `radix_cache.py:467-610`, `_record_remove_event`, and `radix_cache_cpp.py:47` | vLLM queued `BlockStored/BlockRemoved` with parent hash, group, medium, extra keys; SGLang event queue and node insert/remove events | Missing removal event, duplicate store, event hash not matching lookup namespace, event ordering race | Event stream is consistent with cache state: every externally visible store/removal corresponds to one state transition. **LOCAL** | vLLM events carry block/group/medium/MM/LoRA metadata; SGLang’s C++ radix backend explicitly states KV-cache events are unsupported (`radix_cache_cpp.py:47`). |
